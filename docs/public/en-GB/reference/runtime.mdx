What Peren calls on a Worker, what `ctx` contains, and which limits apply. For the programming model, see [Workers](/docs/build/workers/). For web globals, see [Web platform APIs](/docs/concepts/web/).

## Runtime selection

Services run on the JavaScript runtime unless `runtime` is set on the service. Python services use `runtime = "python"` and a `.py` entry module. For the production engine and sandbox plan, see [Python runtime design](/docs/build/python-runtime/).

```toml
[[services]]
name = "api"
runtime = "python"
python_engine = "pyodide" # default; requires PEREN_PYODIDE_ROOT
worker_bundle_path = "worker.py"
compatibility_date = "2026-01-01"
```

## Entry

For JavaScript services, Peren loads `export default` as the Worker entry. The entry module must be JavaScript or CommonJS. A `.wasm` path as the entry is refused. Additional modules may be JavaScript, CommonJS (`.cjs`) or WebAssembly (`.wasm`).

If the default export has no `fetch` function and no fetch listener is registered, isolate load fails with a TypeError requiring `fetch`.

For Python services, Peren executes the entry module and calls methods on `Default(WorkerEntrypoint)`. The class must define `fetch(self, request)` for ordinary HTTP dispatch. Handlers may be synchronous functions or `async` functions. Module-level functions such as `fetch(request, env, ctx)` remain accepted as a compatibility fallback.

## Handlers

| Handler | Signature | Notes |
| --- | --- | --- |
| `fetch` | `(request, env, ctx) => Response \| Promise<Response>` | Required for ordinary HTTP. Must return a `Response`. |
| `scheduled` | `(event, env, ctx) => unknown` | Cron dispatch. `event.cron`, `event.scheduledTime`. |
| `queue` | `(batch, env, ctx) => unknown` | Queue consumer dispatch. |
| `alarm` | `(env, {}) => unknown` | Alarm dispatch. Second argument is an empty object. |
| `tail` | `(events, env, ctx) => unknown` | Tail consumer dispatch. |
| `workflow` | `(event, step, env, ctx) => unknown` | Workflow step dispatch. |
| `activity` | `(event, env, ctx) => unknown` | Required when workflow activity dispatch runs. |
| `webSocketMessage` | `(socket, message, env, ctx) => unknown` | After an upgraded WebSocket receives a message. |
| `webSocketClose` | `(socket, code, reason, wasClean, env, ctx) => unknown` | After an upgraded WebSocket closes. |

Listener fallbacks via `addEventListener` exist for `fetch`, `scheduled`, `queue`, `tail`, `webSocketMessage` and `webSocketClose` when the corresponding default-export method is absent.

Python services use the same handler names as the table as methods on `Default`: `fetch`, `scheduled`, `queue`, `alarm`, `tail`, `workflow`, `activity`, `webSocketMessage` and `webSocketClose` are available in this build. Module-level handlers with `(event, env, ctx)` arguments remain accepted.

Python entry modules receive `WorkerEntrypoint`, `Request`, `Response`, `Headers`, `ctx.waitUntil`, and hydrated binding objects from the `workers` module:

```py
from workers import WorkerEntrypoint, Response

class Default(WorkerEntrypoint):
    async def fetch(self, request):
        body = await request.text()
        print("handled", body)
        return Response("ok", status=202, headers={"x-runtime": "python"})
```

For Pyodide-style examples, Peren also installs a compatibility `js` module with `Request`, `Response`, `Headers`, `WebSocket`, `fetch` and `caches`, plus `pyodide.ffi.to_js` / `to_py` passthrough helpers. Prefer `workers` for new Peren code because it is the stable SDK surface.

### Python Bindings

Python services hydrate configured bindings on `self.env` using the same metadata as JavaScript services. Native KV, D1, R2, queue producers, service bindings, Durable Object namespace fetches, cache, AI, workflow state helpers, and outbound `fetch()` use Peren host calls rather than direct host access from Python code.

Python WebSocket dispatch receives a `WebSocket` object with `id`, `send(message)`, `close()`, and `readyState`. Outbound frames sent during `webSocketMessage` or `webSocketClose` are returned through Peren's shared dispatch bridge. Creating upgrade responses with `WebSocketPair` remains JavaScript-only.

### Python Execution Model

The Python runtime boundary is a JSON host-call protocol between Python code and Peren's Rust hosts. That protocol is the stable contract for runtime parity and keeps bindings, lifecycle dispatch, and examples aligned across the Pyodide and compatibility engines.

The default engine is Pyodide/Wasm, which gives Python services a WebAssembly sandbox, an in-memory filesystem, Pyodide package behavior, and a documented standard-library policy. The compatibility executor uses the system `python3` interpreter and should be treated as a development fallback, not as the production isolation model.

Both engines apply the same Worker-facing constraints:

- Documented runtime exclusions such as `curses`, `dbm`, `ensurepip`, `fcntl`, `multiprocessing`, `threading`, `tkinter`, `venv`, `webbrowser` and platform-specific modules are blocked.
- Host process and socket modules such as `subprocess` and `socket` are blocked; use bindings or `fetch()` for I/O.
- File I/O is relative to an ephemeral invocation filesystem. Writes outside that filesystem are refused, and data is lost after the invocation.

### RPC

Requests with header `x-peren-rpc-method` call that method name on the default export with `args` from the JSON body (`{ "args": [...] }`). Missing methods return status 404. Thrown errors return status 500. Success returns `{ ok: true, value }` with content type `application/vnd.peren.rpc+json`.

## Context

```js
ctx.waitUntil(promise);
```

| Member | Type | Behavior |
| --- | --- | --- |
| `waitUntil` | `(promise) => void` | Registers work drained before the invocation finishes. |

`ctx` has no other members on the live dispatch path.

## Environment

| Source | Shape on `env` |
| --- | --- |
| `[services.vars]` | string |
| `[services.secrets]` / secrets-store refs | string |
| Hydrated bindings | binding objects by configured name |

Peren does not leave internal binding or cache objects on `env`. The global `caches` object comes from `[cache]`, not from `env`. Service assets are served by the node for matching static paths and are not placed on `env`.

Python services receive plain variables and secrets as attributes on `self.env`. Binding metadata is consumed by the runtime boundary and is not exposed as an application variable.

## Limits

Defaults from fleet `[limits]`:

| Field | Type | Default | Live HTTP path |
| --- | --- | --- | --- |
| `max_request_body_bytes` | u64 | 33554432 | Enforced for request and response body size |
| `max_heap_bytes` | u64 | 134217728 | Enforced as isolate heap limit |
| `max_execution_time_ms` | u64 | 30000 | Enforced as wall-clock watchdog |
| `max_subrequests_per_invocation` | u32 | 10000 | Enforced on requests the node makes for the Worker |
| `max_isolates` | usize | 256 | Enforced as process admission capacity |
| `max_cpu_time_ms` | u64 | 30000 | Present in config; not applied when building live HTTP invocation limits |
| `isolate_fair_share_percent` | u8 | 25 | Process scheduling share |
| `checkpoint_threshold_bytes` | u64 | 4194304 | Cell checkpoint threshold |
| `cron_retry_base_ms` | u64 | 2000 | Cron retry base delay |
| `cron_retry_max_attempts` | u32 | 6 | Cron retry attempts |
| `cron_retry_max_backoff_ms` | u64 | 64000 | Cron retry backoff ceiling |
| `max_steps_per_instance` | u64 | 100000 | Workflow step ceiling |

Services may override `max_heap_bytes`, `max_execution_time_ms`, `max_subrequests_per_invocation`, `max_cpu_time_ms`, `isolate_fair_share_percent`, `checkpoint_threshold_bytes` and `max_steps_per_instance`. Override of `max_cpu_time_ms` does not change the live HTTP path until the node wires that field into invocation limits.

When a request or response exceeds `max_request_body_bytes`, Peren refuses the body. When heap or wall-clock execution limits trip, Peren terminates the isolate work for that invocation.

## Compatibility flags

Config validation accepts `no_nodejs_compat` and `no_nodejs_compat_v2`. Flags `nodejs_compat`, `nodejs_compat_v2`, `nodejs_als`, `durable_object_fetch_requires_full_url` and `streams_enable_constructors` are recognized and refused. Unknown flags are refused.
